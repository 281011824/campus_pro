一定位与边界

一句话定位：班主任每天打开一个页面，就能看清本班情况、处理本班事务、留下工作痕迹；数据只读汇聚，录入尽量少，结论必须由人确认。

1.1 要解决的问题

  • 信息分散在学籍、考勤、教务、寝管、政教、企业微信等多个系统，班主任每天重复登录、反复核对。
  • 学生情况靠记忆和纸质记录，期末写评语、做家访、迎检时缺少连续证据。
  • 德育事件“谁登记、谁确认、计多少分”口径不一，容易出现先定性后找证据。
  • 上级要报表、家长要反馈，班主任被动填表，事务性负担重。

1.2 三条产品原则

只读优先，少录入

能自动接入的数据不要求班主任二次录入；必须人工登记的，只记分类、时间与事实，不写长篇材料。

事实与定性分离

系统只呈现“发生了什么”，是否构成违纪、如何处分由政教处按程序裁定，工作台不代替作出结论。

未就绪不估算

数据源未接入、当日未生成、口径未对齐时，明确显示“暂不可用”，不用旧值、估算值或示例数据顶替。

不推家长，不代写

对外发布必须人工签发；家长联系方式与请假事由不进入留痕表；智能体只做提醒与草稿，不替班主任表态。

1.3 明确不做

  • 不替代学籍系统、教务系统、心理测评系统，不另建一套“全量学生画像”。
  • 不做学生成绩排名，不推算原始分，不依据单次成绩生成德育结论。
  • 不自动向家长推送消息，不自动生成处分建议，不代班主任填写评语。
  • 不展示心理测评明细；心理数据独立库、独立密钥，教师端不可见。

2.1 班级编码规则

班级编号统一为四位：2601—2617，前两位表示 2026 级，后两位表示 1—17 班。一个班主任只对应一个班，不跨班、不兼班。徐海潮固定为 2607 班（成长导航试点班）。

2.4 校验落地方式

  • 身份解析：登录会话优先，本地登录账号映射到企业微信 userid；职务与班级由服务端判定，前端不得传 level、agent_id、data_scope。
  • 班级归属：读取账号映射与通讯录职务，取 portal=headteacher 的班级集合；请求的 class_id 不在集合内即拒绝。
  • 覆盖范围：学生名册、成绩摘要、德育台账、出勤周报、学情概览、成长档案与新增记录、学生 / 成绩导入导出、一键备份、家校留痕。
  • 前端配合：非班主任隐藏成长档案、出勤、学情、德育、班务、家校导航；概览不加载学生数据，显示“仅本班班主任可查看本班学生信息”。

4.1

概览

已上线

班主任每天打开工作台的第一屏：用五个数字判断今天要不要重点盯人，用周报和待办决定先做什么。

核心功能

  • 五项指标：本周出勤率、需关注人数、德育积分、归寝异常、本周请假。
  • 本周周报：系统生成草稿，班主任确认后归档，归档后不再修改。
  • 需关注学生 Top 8：展示关注点、状态与建议动作，可一键转介。
  • 本周待办 Top 6：按时间倒序，处理完成即销号。

数据与接口

  • /api/v1/report/weekly、/report/archive
  • /api/v1/report/watchlist
  • /api/v1/todo/list、/growth/numbers
  • 数据来自考勤、归寝、请假、德育、作业与成绩的周汇总。
规则与红线：周报未经人工确认不得归档；指标缺失时显示“暂不可用”，不补数、不估算；待办与周报不含家长电话、心理明细；空态显示“本周暂无”，不摆示例数据。

现状：2607 班指标完整；其余班级待导入名册、成绩与出勤数据后自动呈现。

4.2

成长档案

已上线

以学生为单位，把出勤、德育、奖惩、家访、特长与兴趣连续记录，减少期末集中补材料。

核心功能

  • 本班名册：按姓名或学号搜索，展示学号、姓名、性别、状态。
  • 个体档案：基本信息、近 7 日出勤汇总、近期德育事件、成长记录。
  • 新增记录：特长、兴趣、奖惩、家访四类，可填日期与说明。
  • 名册 Excel：下载模板、导入、导出，按学号覆盖。

数据与接口

  • /api/v1/students、/students/{id}/profile
  • POST /students/{id}/records
  • /files/template|export|import/students
  • 表：students、student_records、dom_attendance、dom_behavior
规则与红线：仅本班班主任可查看与编辑；监护人电话只作存档，不对外推送、不进入导出以外的场景；记录只写事实与时间，不写主观定性；跨班访问一律返回 403。

现状：2607 班有 66 名学生与 150 条成长记录；其他班需先导入名册。

4.3

出勤统计

已上线

把“今天谁没到、这周请了哪些假、出勤率是多少”从翻记录变成一屏可读。

核心功能

  • 本周出勤率与逐日出勤趋势。
  • 今日未到名单（含状态：缺勤、迟到、请假）。
  • 本周请假记录：学生、起止日期、请假类型。
  • 按日、按学生聚合，支持与成长档案联动查看。

数据与接口

  • /api/v1/attendance/week
  • 表：dom_attendance（班级 + 日期 + 学生 + 节次唯一）、dom_leave
  • 来源：智慧班牌、考勤终端、电子请假单。
规则与红线：当日数据未生成时显示“未就绪”，不把“未生成”当作“未到”；请假与归寝口径不一致时暂停该数字并提示对账；不以估算值或昨日值替代；缺口日明确标注。

现状：按月/周演示数据已跑通；真实考勤与请假接口待现场联调。

4.4

学情预警

已上线

用作业提交与考试等第两条线索，尽早发现需要谈一谈的学生，但不替代教学判断。

核心功能

  • 作业提交率与低提交名单（提交率低于 70%）。
  • 最近一次考试等第分布、趋势（上升 / 持平 / 下降）。
  • 需关注学生全量清单，支持转介到班务待办。
  • 成绩 Excel：模板、导入、导出，按考试与学生覆盖。

数据与接口

  • /api/v1/learning/overview、/scores/summary
  • /files/template|export|import/scores
  • 表：dom_homework、dom_scores
  • 来源：AI 批改、教务 / 考务周期导入。
规则与红线：采用等第制，不排名、不换算原始分、不公开学生分数；成绩只作线索，不直接生成德育或处分结论；需关注清单必须能追溯到具体事实（缺交、等第下降等）。

现状：2607 班有 66 条成绩演示数据；真实作业与成绩接口待接入。

4.5

德育量化

已上线

把“政教处登记、班主任确认、计入德育分”拆成清晰的三步，避免先定性后补证据。

核心功能

  • 待确认事件：政教处登记后进入待确认，班主任逐条确认或作废。
  • 确认后才计分；作废保留记录，不删除。
  • 德育台账：近期事件、正负极性、分类、分值、状态。
  • 本周德育积分与班级汇总。

数据与接口

  • /api/v1/moral/summary、/moral/records
  • POST /moral/event（登记）、POST /moral/confirm（确认 / 作废）
  • 表：dom_behavior（pending / confirmed / void）
  • 来源：政教处事件登记、活动与岗位参与。
规则与红线：只写事实，不写定性结论；未经班主任确认不计分；作废必须留痕（确认人、时间）；德育分不作为处分依据；敏感事由、心理内容不入库、不展示。

现状：待确认、确认、作废、台账与积分统计已跑通；真实事件来源以政教处登记为准。

4.6

班务减负

已上线规则待审定

把散落在群消息、口头通知、检查反馈里的事情收进一个待办清单，办完即销号，转介有回执。

核心功能

  • 本周待确认：本周新增 + 上周未销号，按时间倒序。
  • 三类来源：预警转介、家长告知事项、上周遗留。
  • 转介单：从需关注清单生成，附事实与建议动作。
  • L2 回执三态：已接收、处置中、已销号。
  • 销号：人审后留痕，销号后不再出现在列表。

数据与接口

  • /api/v1/todo/list|refer|note|close
  • /todo/referrals、/todo/receipt
  • /api/v1/warning/state
  • 表：todo_items、referral_slips、duns
规则与红线：集中待办独立于“待确认写入”草稿；转介只写事实、不作定性；L1 与 L2 可关联但不继承字段、不回流学生明细；逐级不越级；销号留 userid + post_id + agent_id 三元组审计。

现状：待办、转介、三态回执已跑通。缺口：四色预警 12 条规则经审定数为 0/12，影子模式未启动；劝返台账落点待政教处与招就处现场确认。

4.7

家校协同

已上线（留痕）

把“什么时候因为什么事联系过家长”留成记录，同时严格约束触达方式与信息范围。

核心功能

  • 六类沟通登记：归寝异常、缺勤关注、学业联系、行为观察、家长告知、其他。
  • 沟通记录列表：分类、时间、登记人、状态。
  • 登记后进入本周待办，可归档销号。

数据与接口

  • POST /api/v1/files/family/note
  • /api/v1/todo/list（含 notify 类待办）
  • 表：todo_items（kind=notify）
  • 来源：班主任人工登记，企业微信触达层。
规则与红线：不自动向家长推送；不保存家长电话、住址、请假事由细节；对外发布必须人工签发，智能体不代发；一次沟通一条留痕，不合并、不补写；仅本班班主任可登记。

现状：留痕与待办联动已跑通。缺口：企业微信真实消息通道未启用（当前 mock）；短信兜底未开通；家长端知情与授权流程待合规评估。

数据备份

已上线

让班主任自己能把本班数据带走、留档、迁移，不依赖管理员临时导表。

  • /api/v1/org/bindings、/org/bindings/generate|update|.csv
  • /api/v1/domains/status
规则与红线：学生与成绩导入导出仅本班班主任；教师账号仅校领导、中层干部；备份包含敏感数据，须按保密要求存放，不得上传公网盘；数据库快照用于故障恢复，不作为日常交换格式。

现状：备份包实测可用；映射已按 2601—2617 生成 17 名班主任。

5.2 导入规则

  1. 模板首行为表头，按列名识别；缺少必填列直接拒绝并返回原因。
  2. 空行、缺必填字段的行计入“跳过”，不中断整批。

5.4 账号与班级映射

  • 账号来源：教师账号表，共 219 个；映射记录 228 条，其中班主任端 17 条、教师端 144 条、行政端 67 条。
  • 生成规则：优先教师类班主任，取 17 人一人一班；徐海潮固定 2607；其余按账号顺序分配到 2601—2617 的剩余班级。
  • 复核状态：规则生成的记录统一标“待确认”；政教处可在 CSV 中校正，再通过映射更新接口回写并置为“已确认”。
  • 独立绑定表：映射存于 account_bindings，不写入通讯录职务表，避免每次同步被“离岗回收”清空。
数据管理提醒：映射是权限的根。班主任换班、离职或新增班级时，必须先更新映射，再核对本班学生数据可见性；不要直接在数据库改班级字段。

5.5 数据质量与口径

  • 未就绪不估算：归寝、考勤只认“数据就绪日”；未生成返回“未就绪”，不把未生成当未归。
  • 口径对账：请假与归寝数量不一致时暂停该数字，标注“暂不可用”，通知信息化处核查，不以估算值替代。
  • 最小字段：前端只允许学号、掩码姓名、班级、年级、归寝状态等白名单字段；家长姓名、电话、学生电话、请假事由、心理明细进入黑名单。
  • 心理隔离：心理数据独立库、独立密钥，教师端永不展示明细，仅保留“已测 / 未测”等管理状态。

六关键业务流程

6.1 每日闭环

登录→ 概览看指标→ 出勤核对未到→ 处理待办 / 转介→ 家校沟通留痕→ 销号

建议每天上午课前看一次出勤与待办，下午放学前处理未销号项；需要家长知情的，先人工沟通，再在本班登记一条留痕。

6.2 每周闭环

周报草稿→ 班主任确认→ 归档→ 上周未销号结转→ 转介回执核对
  • 周报由系统按周一 06:50 定时生成草稿（受调度开关控制），未经确认不归档。
  • 上周未销号事项自动进入本周待确认，避免“提了没人管”。
  • 转介单由 L2 回执三态闭环：已接收、处置中、已销号；销号后不再出现。

6.3 每学期闭环

1

  2. 核对班主任与班级映射
  3. 核对教师账号与状态
2

过程数据

  1. 按考试导入成绩
  2. 确认德育事件并计分
  3. 持续登记成长记录
3

留档与复盘

  1. 一键备份本班数据
  2. 归档周报与台账
  3. 核对缺项并补齐

B. 术语

  • 三端：班主任端、教师端、行政端，是导航层；具体权限由职务（post_id）与层级（L1—L6）决定。
  • 派生区：由原始数据聚合出的只读结论区，只给标记与建议，不展示原始作答、分数与心理明细。
  • 待确认红点：本周需要班主任确认或销号的事项集合，独立于两段式写入草稿。
  • 两段式写入：先形成草稿，人工确认后才落业务库，避免智能体直接改数据。
  • 三元组审计：userid + post_id + agent_id 三项同时留痕，保证“谁、以什么职务、通过哪个智能体”可追溯。
  • 影子模式：预警规则先只记录不推送、不进考核，用一段时间核对误报后再正式启用。

C. 文档依据
