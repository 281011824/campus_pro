三、核心技术适配点

3.1 业务调用方式：Redis 代理 → 直接函数调用

❌ 之前：website 代理 → Redis → worker

# website/app/api/v1/head_teacher_workbench.py
async def head_teacher_workbench_proxy(request):
    # 72 条路由全部走这个函数
    client = get_head_teacher_workbench_client()
    result = await client.request(
        method=request.method,
        path=request.url.path,
        query=query, body=body,
    )
    return Response(
        content=result["body"],
        status_code=result["status"],
    )

✅ 之后：FastAPI 直接调用业务函数

# website/app/api/v1/head_teacher_workbench.py
from app.business import worker_bridge

async def api_handler(request):
    # 直接调用业务模块，无 Redis
    response = worker_bridge.handle(
        method=request.method,
        path=request.url.path,
        query=query,
        body=body,
        auth_user=auth_user,
    )
    return JSONResponse(
        response.body,
        status_code=response.status,
    )

3.2 从 Flask server.py 提取的业务路由核心

班主任端 app/server.py 是 60+ 业务路由的核心调度，使用 Python 标准库 http.server.BaseHTTPRequestHandler。它已经把路由逻辑和业务实现（org.py/growth.py/push.py 等）完全解耦了——路由函数签名是：

def handle_XXX(ctx, params, body_json):
    # ctx 是认证上下文 dict
    # params 是 URL 参数
    # body_json 是请求体 dict 或 None
    return {"status": 200, "body": {...}, "content_type": "application/json"}

这个签名本身就很容易被 FastAPI 直接包装，不需要 Redis 中转。

3.3 SQLite 连接：已完美适配

worker 里的 db.py 已经是生产可用的 SQLite 配置：

  • PRAGMA journal_mode=WAL — 写不阻塞读
  • PRAGMA foreign_keys=ON — 外键约束
  • timeout=10s — 忙等待，避免瞬时冲突
  • 完整 SCHEMA 常量 — 17 张表，初始化幂等
  • _ensure_columns() — 兼容已有库的补列逻辑

直接搬过来即可，无需改动。

3.4 Flask server.py → worker_bridge 适配层

新建一个适配模块，把 Flask server.handle_XXX(ctx, params, body_json) 调用封装成 FastAPI 能直接 import 调用的普通 Python 函数：

# website/app/business/worker_bridge.py
import json
from app.business import server, db, org
from app.business.server import ApiError

class BridgeResponse:
    def __init__(self, status, body_dict_or_str, content_type="application/json"):
        self.status = status
        if isinstance(body_dict_or_str, dict):
            self.body = body_dict_or_str
        elif isinstance(body_dict_or_str, str) and body_dict_or_str.startswith("{"):
            self.body = json.loads(body_dict_or_str)
        else:
            self.body = body_dict_or_str
        self.content_type = content_type

def handle(method, path, query_string="", body_json=None, auth_user=""):
    # 构造 ctx（模拟 server.py 的上下文对象）
    ctx = {"user_id": auth_user or "-",
           "post_id": "-", "agent_id": "-",
           "level": "L1"}
    try:
        result = server.route_dispatch(method, path, ctx, query_string, body_json)
        return BridgeResponse(result["status"], result["body"])
    except ApiError as e:
        return BridgeResponse(e.status, {"code": e.code, "error": e.message})

四、搬迁路径（按易理解度排序）

  1. Step 1 · 搬业务模块进 website
    将 tasks/head_teacher_workbench/app/ 下的 16 个 Python 文件拷贝到 website/app/business/，让 FastAPI 能直接 import 这些业务模块。保留原始文件名不动。这是纯文件搬运，零改动。
  2. Step 2 · 写 worker_bridge 适配层
    新建 website/app/business/worker_bridge.py，把 server.py 的 route_dispatch 包装成 FastAPI 能直接调用的普通 Python 函数。这是唯一需要写新代码的地方，而且代码量很小（约 40 行）。
  3. Step 3 · 改 head_teacher_workbench.py 路由
    把原来"72 条路由全部走 Redis 代理"改成"72 条路由全部走 worker_bridge.handle()"。路由注册方式不变，只是 handler 函数体从调 Redis 客户端改成调 bridge。
  4. Step 4 · 改 main.py lifespan 初始化
    把 lifespan 里的 Redis 初始化/关闭代码删掉，加上 db.init_db() + org.sync_directory()。启动时自动建表 + 同步通讯录。
  5. Step 5 · 更新 requirements.txt
    移除 redis 依赖（或保留为可选），SQLite 不需要额外依赖（stdlib sqlite3）。
  6. Step 6 · 本地单元测试
    跑 website/tests/ 和 tasks/head_teacher_workbench/tests/ 确认功能正确。特别检查登录态 + 业务调用链。
  7. Step 7 · 部署到台式机 & 验证
    打包上传，重启 htw-website，验证 72 条路由能直接返回业务数据（不经过 Redis），登录页正常，数据库连接正常。
  8. Step 8 · 停 htw-worker & htw-redis
    确认单体运行稳定后，停掉 worker 和 Redis 单元（systemctl stop + disable）。保留原始 SQLite 数据文件不动。

五、风险与回滚

风险 · server.py 的 Flask Handler 签名
worker 的 server.py 和 班主任端 的 server.py 可能有细微差异（worker 版本可能适配过 Redis 线协议）。需确认 route_dispatch 函数签名一致。
风险 · org.sync_directory() 需要 fixtures
启动时需要 data/fixtures_2607.json 等文件在正确路径。business/config.py 的 ROOT 路径需重新对齐 website 的目录结构。
回滚方案
保留旧 website 代码在 /opt/school_pro/website.bak/，Redis 和 worker 单元不删只 disable。任何时候 systemctl restart htw-worker htw-redis + 旧 website 即可恢复三段式。

迁移时数据完整性

SQLite 数据文件 /opt/school_pro/runtime/dywork.db 在整个过程中 不做任何结构变更，只做读操作（db.py 的 init_db 是幂等 CREATE TABLE IF NOT EXISTS）。单体 FastAPI 直接使用同一份 db 文件，数据零迁移风险。
