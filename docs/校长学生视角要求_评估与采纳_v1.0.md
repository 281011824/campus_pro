# 校长学生视角要求 · 评估与采纳 v1.0

- 日期：2026-11-24
- 评估对象：`growth-nav-测试包-20261110`（校长给的学生成长导航系统设计手稿/测试包）
- 评估方式：本地把参照项目跑起来 → 用学生账号逐页实测 → 归纳要求 → 判断合理性与可用性 → 摘出可落地部分
- 结论用途：指导本系统（班主任工作台）学生角色模块实现，口径与《需求基线 v2.0》红线一致

## 一、参照项目本地实测状态

参照项目原为 PostgreSQL 双库（`growth_nav` / `growth_nav_psych`），本机无法安装 PostgreSQL，已改为 SQLite 调试跑通（仅调试环境，不代表生产方案）。

| 项 | 结果 |
|---|---|
| 依赖 | 补装 `aiosqlite`、`pydantic-settings`、`greenlet` |
| 模型适配 | `JSONB` → 通用 `JSON`；`BIGINT` 在 SQLite 下编译为 `INTEGER` 以保留自增 |
| 建表 | 跳过 Alembic，`metadata.create_all` 建业务库 45 表 + 心理库 1 表 |
| 种子 | 8 个脚本按序跑通（seed → scales → w3 → demo → p1 → family → p16 → p1a） |
| 服务 | `uvicorn app.main:app --port 8090`，`/health` 返回 `code=0, db=up` |
| 学生登录 | `13800000001 / Growth@2026` 成功，返回 `role=student`、`bindStatus=bound` |

浏览器实测（学生账号李同学，控制台 0 error）：

| 页面 | 实测结果 |
|---|---|
| 登录 / 首页 | 登录成功跳首页，顶部「李同学」，底部导航：首页/测评/画像/成长/我的 |
| 测评中心 `/assess` | 「八项诊断」：在线 5 项 + 3 张说明卡（学科基础·纸考导入 / 价值观·暂未开放 / 身心状态·心理区施测） |

## 二、校长对学生视角的要求清单（归纳）

从参照项目的登录规则、页面结构、README 红线与实测文案归纳为 12 条，逐条判断。

| # | 要求（校长视角） | 出处 | 判断 | 处理 |
|---:|---|---|---|---|
| 1 | 学生登录=学籍号/手机号 + 口令；学籍号通道限校内网段 | README 登录规则、auth.py | 合理 | 采纳「学号=账号」，初始密码=学号（用户定）；手机号+短信暂不做（见 §四） |
| 2 | 学生令牌只管本人，取他人数据一律 403 | permissions.py、红线 5 组 | 合理且必须 | 采纳：服务端按会话强制本人作用域 |
| 3 | 学生首页四频道：目标与陪伴 / 我的空间 / 批次进度 / 分享成长 | 实测 /mine | 部分合理 | 原项目无测评/空间/分享数据域，剪裁为「档案 / 德育 / 考勤 / 作业」四卡 |
| 4 | 测评中心「八项诊断」，并明确 3 项不在本页完成 | 实测 /assess | 合理但无数据域 | 不搬（无题库、无量表授权）；只学「如实说明哪些做不了」的口径 |
| 5 | 画像用雷达图 + 优势/待发展标签，不给总分、不排名 | 实测 /profile、红线 2 | 合理 | 采纳「无总分、无排名」原则；不搬雷达（本系统五维与德育量化分离） |
| 6 | 成长时间轴只展示正向记录，按日期倒序 | 实测 /timeline | 合理 | 采纳：学生端展示本人德育事件明细（仅 confirmed） |
| 7 | 隐私授权：谁看过我、授权开关可撤销、每次查看留痕 | rights.py、隐私设计 | 合理但目前无受众 | 缓做（本系统暂无第三方查看学生数据的角色入口） |
| 8 | 分享成长：生成分享码，访客免登录只看授权范围，带水印、朋友档≤14 天 | shares.py | 与红线冲突 | 不采纳：数据不出校、报告字段白名单；不开放免登录访客入口 |
| 9 | 待办与催办：测评/四维未完成自动生成待办，完成即消卡 | 实测 /me/reminders、P1.6 | 设计合理 | 暂不做（本系统无通知中心）；先保留「作业/考勤」卡片提示 |
| 10 | 成长空间：形象装扮、成长值/等级、16 徽章、打卡热力图 | 实测 /mine、P1.6 | 教育价值有限 | 不采纳（游戏化非教学必需，且易引导学生比等级） |
| 11 | 家长端 L0/L1/L2 三层信息模型，家长令牌只走 /family/* 铁闸 | family.py、P1.5 | 合理但属独立立项 | 不采纳本期；仅继承「家长永远拿不到原始作答与心理字段」红线 |
| 12 | 心理区独立登录、物理隔离；教师/年级/领导拿不到原始作答与维度分 | psych.py、红线 1/2 | 合理且必须 | 采纳：学生端不出现任何心理/原始作答字段；学生会话进管理端一律 403 |

共同原则（跨条目的 4 条硬约束）：
1. **只本人**：任何接口先按会话解析学生身份，不接受前端传学号查别人。
2. **无排名**：不给班级排名、班级均值对比、他人明细。
3. **不臆造**：无数据一律「暂不可用」，不用示例值或旧值顶替（与《需求基线 v2.0》「降级不估算」一致）。
4. **口径分离**：德育量化单独计分、不并入五维、不折算、不替代。

## 三、可嵌入本系统的部分（采纳清单）

| 采纳项 | 在参照项目中的原型 | 本系统落地方式 |
|---|---|---|
| 学号即账号 | 学籍号+口令（机房通道） | `POST /api/v1/login` 增加 student 分支；账号=学号，初始密码=学号（SHA-256 摘要） |
| 登录后直达个人门户 | next 分支按角色落页 | next 增加 `/api/student` 分支 |
| 学生只能看本人 | token scope 个人域 | `/api/v1/student/*` 全部按会话取 `student_id`，越权 403 |
| 个人档案卡 | 画像页顶部身份区 | 学号/姓名/班级/专业/年级（白名单字段） |
| 德育得分与明细 | 成长时间轴 + 画像标签 | 本周期总分（基准 100、仅 confirmed）+ 事件明细（日期/指标/分值/事由） |
| 单人趋势折线 | 成长页可视化 | 本周期每日净得分折线（原生 SVG，无班级对比） |
| 考勤摘要 | 待办/进度卡 | 今日到课状态 + 本周出勤率 |
| 作业摘要 | 批次进度卡 | 本周提交率 |
| 空态不臆造 | 测评中心 3 张说明卡 | 无数据项渲染「暂不可用」 |
| 角色路由闸 | 中间件 403 + 审计 | 学生会话访问班主任/政教/管理接口 403 |

## 四、不采纳 / 缓做及理由

| 项 | 处理 | 理由 |
|---|---|---|
| 手机号 + 短信验证码登录 | 不做 | 学生手机号台账与短信网关均未接入；且会增加个人信息收集面 |
| 八项诊断 / 心理测评 / 雷达画像 | 不做 | 题库与量表授权不具备；心理数据须独立立项 |
| 成长空间装扮 / 成长值 / 徽章 | 不做 | 游戏化激励非教学必需，易滋生等级攀比，与「不排名」口径相悖 |
| 分享码 + 访客免登录 | 不做 | 与「数据不出校」「报告字段白名单」两条红线直接冲突 |
| 家长端 L0/L1/L2 | 缓做 | 独立立项；本期只继承其隐私红线 |
| 隐私授权「谁看过我」 | 缓做 | 当前无第三方查看入口，先留接口位 |
| 催办通知中心 | 缓做 | 本系统无通知中心；先用卡片内提示 |

## 五、落地口径（写入实现与测试）

1. 账号=学号，初始密码=学号；学生首次登录不强制改密（改密留后续版本）。
2. 失败 5 次锁 60 秒（复用现有双维限流），返回 429。
3. `/api/v1/student/me|moral|attendance|homework` 四接口，非学生会话 403。
4. 德育：仅 `confirmed` 计分，基准 100，不返回排名与班级聚合。
5. 空数据：统一 `data=null` + 前端文案「暂不可用」。
6. 字段白名单：`student_id / name / class_id / major / grade`，不出现家庭住址、家长电话、心理明细。
